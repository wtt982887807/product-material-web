# 产品要素工作台

[打开网页](https://wtt982887807.github.io/product-material-web/)

用目标产品合同更新近似产品模板，保留原话术与格式。合同和模板在浏览器本机处理，不上传服务器，不需要安装 Skill。

## 使用

1. 选择一份目标产品合同（DOCX 或 DOC）。
2. 选择一页通、PPT、海报模板中的至少一份（DOCX / PPTX）。模板可以是其他产品。
3. 需要更新一页通公司介绍时，上传最新公司介绍 DOCX。网页匹配双栏介绍或规模／奖项／经验指标栏，只对 Word 的对应区域生成修订。当前浏览器会记住最近一次有效版本，未上传新文件时自动沿用；其他电脑或浏览器首次使用需上传一次。
4. 右上角制作月份默认北京时间当月，可手动修改，也可恢复当月。核对完成后改月份，无须重新读取合同；文件名和下载包同步更新，正文业务日期不变。
5. 核对页面显示有依据的修改、保留原值的待核项，以及合同或最新公司介绍的出处。需要时可填写补充资料。
6. 下载整包或单个文件。黄色参数仍需确认，下载成功不代表全部业务信息已核实。

## 更新范围

- 合同决定目标产品；模板决定字段、表达和版式。
- 同主体、份额、渠道、期间和条件的同一事实共享核对，再按各物料的位置回写。
- 修改有依据的产品要素差异，以及上传公司介绍中能明确匹配的一页通公司信息。公司、股东、信托及投资顾问按主体分别匹配，保留模板布局、独立免责及更名说明；PPT 和海报不更新公司介绍。其他营销图文、历史业绩、人员履历保持模板原样。
- 合同缺项保留各模板自己的旧值，局部标黄并添加批注。无法可靠对应的条款会显示“需要人工核对”，不会冒充合同已确认。
- Word 先接受支持的旧修订，再生成本轮真实修订和批注；不支持的结构修订会明确报错。
- 普通 PPT 只输出自身产品要素页及续页，信托底层产品页排除；海报完整输出。
- 输出文件名按合同更新产品名称，并使用选定的制作月份；未手动选择时使用开始核对时的北京时间当月。保留模板的年月格式及简称风格，PPT 追加一次“产品要素”。

## 当前能力边界

当前版本使用本地规则和合同检索，不包含远程大模型服务。支持可编辑的 DOCX/PPTX 文字及表格、旧 DOC 合同正文。扫描件、图片内文字、PDF 和复杂图形内文字不支持自动更新；陌生字段、复杂适用条件仍可能需要人工核对。图片本身不会重新生成。

浏览器导出会验证文件结构、修改范围与关系引用；不能替代本机 Word/PowerPoint 的排版检查。三组验收样本已另行使用原生 Office 打开和渲染。保留模板中的原有标黄、批注和不属于本轮的业务日期。

## 本地运行与开发

需要 Node.js 20 或更新版本。在本目录运行：

```sh
npm install
npm test
npm run serve
```

浏览器打开 `http://127.0.0.1:8766/`。运行网页本身不依赖 Node.js；GitHub Pages 直接托管根目录即可。无需本机绝对路径、API Key 或 Office 安装。

合同和模板仅驻留本页内存；重新选择文件或关闭页面可结束本轮处理。最近一次有效的公司介绍保存在当前浏览器的本地数据库中，可用“清除已保存版本”移除；清理浏览器网站数据后需要重新上传。若浏览器禁止保存，会明确提示仅本次可用。无效的新文件不会覆盖之前保存的版本。仓库不保存真实合同、模板、公司介绍和测试生成物。

第三方组件及许可证位于 `vendor/`。旧版 Skill 项目独立保留在 [product-material-skills](https://github.com/wtt982887807/product-material-skills)。
