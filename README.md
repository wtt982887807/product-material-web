# 产品要素工作台

[打开网页](https://wtt982887807.github.io/product-material-web/)

用目标产品合同更新近似产品模板，保留原话术与格式。合同和模板在浏览器本机处理，不上传服务器，不需要安装 Skill。

## 使用

1. 选择一份目标产品合同（DOCX 或 DOC）。
2. 选择一页通、PPT、海报模板中的至少一份（DOCX / DOC / RTF / PPTX）。模板可以是其他产品。Word 先自动接受旧修订，旧版格式自动转为 DOCX，原文件保持不变。
3. 网页已内置 2026.10 修正版公司介绍（规模日期为2026年6月末），首次使用及其他电脑也无需上传。已知的旧版缓存会自动改用修正版，其他上传版本按原有规则保留。网页匹配双栏介绍或规模／奖项／经验指标栏，只对 Word 的对应区域生成修订。上传新版 DOCX 后，当前浏览器会记住并优先沿用新版；可点击“恢复网页内置版本”。
4. 右上角制作月份默认北京时间当月，可手动修改，也可恢复当月。核对完成后改月份，无须重新读取合同；文件名和下载包同步更新，正文业务日期不变。
5. 核对页面显示有依据的修改、保留原值的待核项，以及合同或最新公司介绍的出处。需要时可填写补充资料。
6. 点击生成后，进度、失败原因和下载入口会显示在按钮旁。成功后自动尝试下载整包；浏览器未开始下载时，直接点击下载包或单个文件链接。单份模板读取或生成失败时，其他正常物料仍可下载，未完成文件及原因会逐项显示并写入审阅清单；没有有效输出时不会生成空包。重复模板自动合并，误选为模板的合同自动跳过。黄色参数仍需确认，下载成功不代表全部业务信息已核实。

## 更新范围

- 合同决定目标产品；模板决定字段、表达和版式。
- 同主体、份额、渠道、期间和条件的同一事实共享核对，再按各物料的位置回写。
- 修改有依据的产品要素差异，以及上传公司介绍中能明确匹配的一页通公司信息。公司、股东、信托及投资顾问按主体分别匹配，保留模板布局、独立免责及更名说明；PPT 和海报不更新公司介绍。其他营销图文、历史业绩、人员履历保持模板原样。
- 合同缺项保留各模板自己的旧值，局部标黄并添加批注。无法可靠对应的条款会显示“需要人工核对”，不会冒充合同已确认。
- Word 先在副本中接受旧修订（包括表格属性历史、行／单元格增删和移动修订），再生成本轮真实修订和批注。复杂结构会自动交给完整 Office 转换组件；损坏文件或无法可靠处理的输入仍会明确报错。
- 完整 Word 转换后，若发现引用了不存在内容的旧批注，自动清理该悬空引用并提示；正文和仍有内容的旧批注保留，避免导出的文件在 Word 中无法打开。
- 普通 PPT 只输出自身产品要素页及续页，信托底层产品页排除；海报完整输出。
- 信托等双栏要素表按各自的标签与值分别核对，历史业绩表排除；两层合计费用没有相同口径依据时保留待核。裁剪 PPT 后，指向未交付页的点击／悬停跳转和相对翻页动作会移除并列入处理提示，可见文字及图形保留。
- 输出文件名按合同更新产品名称，并使用选定的制作月份；未手动选择时使用开始核对时的北京时间当月。保留模板的年月格式及可确认的简称风格，PPT 追加一次“产品要素”。无法可靠识别简称或期数占位时，保留【渠道／物料／月份】前缀并采用合同产品名，不阻断生成；输出重名自动加序号，全部文件保留。

## 当前能力边界

开放安排分别识别每周星期、每月日期和“每月第几个周几”。月内星期规则按完整序列核对，例如合同的“第一个、第三个周三”会同步到一页通和 PPT，并保留模板的中文或数字写法、连接词和其他条款；无法对齐的序列或相互冲突的依据保留待核，不截取其中一个顺序写入。

Excel 的“档期起始日期”和“档期结束日期”共同组成完整开放区间。存在“参与和退出／仅参与”分段时，优先使用补充资料中的前后开放日天数，否则依据模板的完整分段规则或旧分段日期，按沪深股票交易日重算各段日期，同步更新 PPT、海报及一页通。不会把周末调休当作交易日；预约截止日独立核对。目前内置交易所公告的 2025、2026 年休市日历。只有起始日期、分段规则冲突、交易日总数不符、境外交易日或日历尚未覆盖的年份，均只应用明确提供的日期，其他分段保留待核并说明原因。

核对页面支持两种补充方式：四行独立补充（本次开放日／开售日、业绩报酬、业绩比较基准、产品代码），或点击选择/直接拖入 XLSX 产品日历（每次一份、30 MB 以内）。每行单独预览、确认应用；空白和未操作的行不会写入下方要素。开放期规则直接根据合同提取并核对，不放入补充区，Excel 中的开放期或锁定期也不会覆盖合同规则；本次开放日期区间和区间内的交易日分段仍可补充。

业绩报酬使用数字表单：单档填写计提基准、提取比例两个数字；分段填写两个递增基准及两档提取比例，共四个数字。可填`2.50`或`2.50%`，不会预填示例值。按模板对应位置仅替换数字，保留“计提基准／计提标准”等原话术及 Word 审阅修订。表单档数与模板不匹配或数字不完整时先提示，不进行半套更新。Excel 和下方分口径卡片继续支持文字解析。

补充和 Excel 均先展示识别结果，再由用户确认应用；本次开放日、开售日及募集日期按同一期日期统一更新，预约日期保持独立，Excel 显示产品行和来源。相同口径只显示一张补充卡片，A/B 份额及不同渠道分别保留。点击“确认无误”会保留对应模板原值，取消该事项本轮新增的待核标黄和批注；Word 中的真实文字修改仍以审阅修订输出。可撤销确认，任何补充或确认变更后须重新生成下载文件。

当前版本使用本地规则和合同检索，不包含远程大模型服务。支持可编辑的 DOCX/PPTX 文字及表格、DOC/RTF 模板自动转换、旧 DOC 合同正文。扫描件、图片内文字、PDF 和复杂图形内文字不支持自动更新；陌生字段、复杂适用条件仍可能需要人工核对。图片本身不会重新生成。

旧 DOC/RTF 及复杂旧修订按需使用浏览器内的 LibreOffice / ZetaOffice 转换组件。合同和模板均按实际内容识别格式，旧 DOC 合同优先快速读取，必要时自动转为 DOCX；普通 DOCX 不加载该引擎。底纹辅助预处理遇到不支持的结构时改由完整引擎转换，并提示核对表格底色，不要求用户先手动另存。首次约下载 50 MB 引擎资源，需要支持共享内存的桌面浏览器和充足内存。转换在本机内存进行，不把合同或模板发送给转换服务。转换可能产生 Office 软件之间的排版差异，最终请在 Word 中审阅。组件来自官方 CDN，其运行资源地址会由官方更新，依赖及许可证见 `converter/` 和 `vendor/`。

浏览器导出会验证文件结构、修改范围与关系引用；不能替代本机 Word/PowerPoint 的排版检查。三组验收样本已另行使用原生 Office 打开和渲染。保留模板中的原有标黄、批注和不属于本轮的业务日期。

辅助格式或导航兼容问题不会阻断整批处理；正文不可读、未定位到产品要素、合同名称无法确定、原文位置不一致、必要资源缺失等情况仍会停止相应文件，防止输出仅改名或内容不完整的物料。

## 本地运行与开发

需要 Node.js 20 或更新版本。在本目录运行：

```sh
npm install
npm test
npm run serve
```

浏览器打开 `http://127.0.0.1:8766/`。运行网页本身不依赖 Node.js；GitHub Pages 直接托管根目录即可。无需本机绝对路径、API Key 或 Office 安装。

合同和模板仅驻留本页内存；重新选择文件或关闭页面可结束本轮处理。仓库内置已授权的 2026.10 版公司介绍两种版式文字，不包含原始 Word 文件和作者元数据。另行上传的有效新版保存在当前浏览器，可用“恢复网页内置版本”移除覆盖；清理浏览器数据后仍可使用内置版。若浏览器禁止保存，会明确提示上传版仅本次可用。无效的新文件不会覆盖之前保存的版本。仓库不保存真实合同、模板和测试生成物。

第三方组件及许可证位于 `vendor/`。旧版 Skill 项目独立保留在 [product-material-skills](https://github.com/wtt982887807/product-material-skills)。
